# HegelBench-ZH Agent 回答评分标准

本 rubric 只评估 Agent 的原始回答，不用于给知识卡打分。评审前必须保存回答原文、实际检索证据和运行配置；评分时隐藏模型、提示词和系统名称，不能先由人修订答案。

## 评测单位

一次评分对应一个固定的“问题—检索结果—原始回答”三元组。以下内容必须冻结：

- 题目 ID 与题目文本；
- 知识库数据版本或 Git commit；
- 检索器、分段、Top-K 和重排配置；
- 模型、系统提示词与采样参数；
- 未经人工修改的回答原文；
- 实际返回给模型的证据 ID 和文本片段。

模型和系统信息在评分完成后解盲。若证据未实际进入模型上下文，不能把它算作回答的证据。

## 评测流程

1. 固定问题、数据版本、模型和检索配置。
2. 保存未经人工修改的模型回答及实际检索证据。
3. 先标记检索结果，再由评审者在盲态下独立评分。
4. 保留每位评审者的原始分数；出现明显分歧时再仲裁。
5. 汇总错误后，只在开发集上修改知识库、检索或提示词。
6. 使用相同开发集复测，并在未参与调试的保留集做最终比较。

## 检索结果标记

检索质量和回答质量分开记录。召回程度与污染情况是两个独立字段：命中关键证据的结果仍可能同时包含错误语境或答案泄露，不能用一个标签覆盖这两类现象。

召回程度：`hit / partial_hit / miss`

| 标记 | 含义 |
|---|---|
| `hit` | 关键证据已召回，足以支持题目主要要点 |
| `partial_hit` | 召回部分相关证据，但缺少关键段落或限定 |
| `miss` | 没有召回可支持主要回答的证据 |

污染情况：`none / wrong_context / answer_leakage / other`

| 标记 | 含义 |
|---|---|
| `none` | 未发现会影响评测有效性的污染 |
| `wrong_context` | 混入错误实体、著作、章节或概念语境 |
| `answer_leakage` | 检索内容泄露标准答案、评分要点或测试集标注 |
| `other` | 存在其他污染；必须在备注中具体说明 |

同时记录模型在证据不足时的行为：`abstained / qualified / unsupported_answer`。检索失败不自动等于回答幻觉，但模型在没有证据时仍给出无保留的确定答案，应在“证据支持”和“解释诚实性”中扣分。

## 通用分值锚点

六个维度均使用整数 0–4 分，不使用半分，也不使用 `N/A`，以保持不同系统之间可比：

| 分数 | 通用含义 |
|---:|---|
| 0 | 严重错误、与问题无关，或关键内容完全没有证据支持 |
| 1 | 有少量相关内容，但严重缺失、误导或多数关键判断不成立 |
| 2 | 基本方向正确，但缺少关键限定、论证环节或充分证据 |
| 3 | 主要内容准确完整，只有局部遗漏或不影响结论的小问题 |
| 4 | 准确、可追溯、边界清楚，并以适合目标学习者的方式完整作答 |

通用锚点用于统一分数的大致严重程度；当通用锚点与下表的维度专用锚点存在歧义时，**维度专用锚点优先于通用锚点**。例如，回答没有文本证据不必自动把“问题相关性”判为 0，但会直接影响“证据支持”。

## 评分维度

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 | 4 分 |
|---|---|---|---|---|---|
| 概念准确性 | 核心含义相反或严重混乱 | 提到相关术语但关键关系大多错误 | 大体正确，缺少影响理解的重要限定 | 主要概念和关系准确，仅有次要遗漏 | 概念、关系、适用边界及必要限定均准确 |
| 文本与论证脉络 | 编造或根本错置著作、章节、阶段 | 只给出错误或高度误导的脉络 | 著作大体正确，但论证位置和作用较弱 | 位置和论证作用基本准确，有轻微不精确 | 准确说明文本位置、前后环节、论证作用和适用边界 |
| 证据支持 | 没有任何关键主张得到支持，或关键主张被证据反驳、证据无关、证据伪造 | 只有少数关键主张得到检索证据支持，多数仍无依据 | 部分关键主张受支持，仍有明显证据缺口 | 几乎所有关键主张可追溯，只有次要缺口 | 所有关键主张均由实际检索证据支持，且引用关系清楚 |
| 解释诚实性 | 把争议、推测或后世理论冒充无争议原意 | 原典、编者概括和二手解释严重混杂 | 没有明显编造，但层次和不确定性说明不足 | 基本区分不同层次，并标出主要争议或限制 | 清楚区分原文、转述、教学解释和学术分歧，证据不足时主动限缩或拒答 |
| 问题相关性 | 答非所问 | 只回应边缘问题，遗漏核心任务 | 回答主要问题的一部分 | 完整回应显性问题，少量隐含误解未处理 | 完整回应问题，并识别和纠正问题中隐含的常见误解 |
| 教学价值 | 表达混乱或强化误解 | 难以理解，结构妨碍学习 | 基本可懂，但组织一般或缺少必要铺垫 | 清楚、分层，能帮助学习者继续阅读 | 通俗而不失真，解释前置概念、关键步骤并给出合适的后续学习路径 |

## 严重错误

出现任一项即标记 `critical_failure`，总分不能抵消：

- 编造黑格尔原文、页码、章节、版本或参考文献；
- 核心概念含义相反，足以使学习者形成根本误解；
- 错置主要著作或论证阶段，并以此支持答案核心结论；
- 把后世有争议解释冒充黑格尔无争议原意；
- 引用真实来源，但该来源不支持答案中的关键主张；
- 在检索证据明确反驳回答时，仍无说明地坚持相反结论。

严重错误必须记录对应原句、证据 ID 和判定理由，不能只勾选而不说明。

## 项目判定区间

以下区间用于本项目版本比较，不宣称是普遍哲学答案标准：

| 结果 | 条件 |
|---|---|
| `strong` | 无 `critical_failure`，总分 21–24，且所有维度至少 3 分 |
| `usable_with_revision` | 无 `critical_failure`，总分至少 16，“概念准确性”和“证据支持”均至少 2 分，但未达到 `strong` |
| `failed` | 不满足以上两类的所有情况，包括出现 `critical_failure`、总分不高于 15，或“概念准确性”“证据支持”任一低于 2 分 |

总分主要用于同一评测集上的版本比较。不能仅凭总分宣布系统“理解黑格尔”，也不能用较高教学表达分抵消来源错误。

## 分歧处理

建议由两位评审者独立评分。任一维度相差 2 分以上、`critical_failure` 判定不一致，或项目判定不一致时，必须进入仲裁：

1. 保留两份原始评分，不用简单平均值覆盖分歧。
2. 对照回答原句、证据和评分锚点记录分歧原因。
3. 判断问题来自答案歧义、证据不足、题目不清还是 rubric 不充分。
4. 记录仲裁分数和理由；若题目本身有问题，修订题目并提升数据版本。

汇总报告至少同时给出平均总分、`critical_failure` 率、各维度均分、检索命中率和评审一致性，避免一个总分掩盖具体失败类型。
